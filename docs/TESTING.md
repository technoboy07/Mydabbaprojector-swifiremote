# Testing

## Automated tests

```bash
./gradlew testDebugUnitTest      # 43 JVM tests, no device needed
node tools/crypto-selftest.js    # phone-side SHA-256/HMAC vs Node's crypto (600+ vectors)
./gradlew lintDebug
```

| Test class | Covers |
|---|---|
| `ProtocolTest` | Pair proof, session key, confirm and request signature match fixtures **generated by `crypto.js`**, so Java and the browser agree byte for byte. RFC 4231 HMAC vector. Hex helpers, constant-time compare |
| `PairingManagerTest` | 80-bit code alphabet, single use, replay of a pairing transcript, closed pairing window, expiry rotation, rotation after 5 failures, malformed input, normalisation (O→0, I/L→1) |
| `SessionAndAuthTest` | Valid signed request, missing/malformed headers, tampered body/path/method, wrong key, unknown session, replayed nonce, stale and future timestamps, revoke, revoke-all, idle expiry, absolute expiry despite activity, persistence/reload, corrupt store, LRU eviction at 5 sessions, nonce cache TTL and bound |
| `PolicyAndRoutingTest` | Host/Origin/Sec-Fetch-Site rules (DNS rebinding, `null` origin, https origin), private-IPv4 detection, exact command allowlist (`up`, `SHELL`, `UP; reboot` rejected), text sanitising and length, every command routed, accessibility-off blocks navigation but not audio, pointer delta bounds, gestures unavailable, rate limiter refill |
| `DirectionalFinderTest` | 3×3 launcher grid neighbours, edges, beam preference over closer diagonals, first-item choice, empty boxes |

**Verified without a device** (this repository's own check): the phone UI was driven in a mobile-
size browser against a mock of the API that applies the same signature checks. QR auto-pairing,
signed status, D-pad/OK/Back/volume, touchpad move then tap (ordering preserved), text send,
hold-to-repeat stopping on cancel and on window blur, disconnect, and wrong/short codes all behaved
as expected.

**Not verified yet:** anything that needs the real projector (accessibility actions, gestures,
volume, network rebinding). Use the matrix below.

### Malicious-request checks (from a laptop on the LAN)

```bash
IP=192.168.1.42; P=8765
curl -s -X POST http://$IP:$P/api/command -H 'Content-Type: application/json' -H "Origin: http://$IP:$P" -d '{"cmd":"HOME"}'
#   -> 401 UNAUTHORIZED            (no signature)
curl -s http://$IP:$P/api/hello -H 'Host: evil.example:8765'
#   -> 403 FORBIDDEN_ORIGIN        (DNS-rebinding style Host)
curl -s -X POST http://$IP:$P/api/pair -H 'Content-Type: application/json' -H 'Origin: http://evil.example' -d '{}'
#   -> 403 FORBIDDEN_ORIGIN
curl -s -X POST http://$IP:$P/api/pair -H "Origin: http://$IP:$P" -d 'x=1'
#   -> 415 UNSUPPORTED_MEDIA_TYPE
head -c 10000 /dev/zero | curl -s -X POST http://$IP:$P/api/pair -H 'Content-Type: application/json' -H "Origin: http://$IP:$P" --data-binary @-
#   -> 413 PAYLOAD_TOO_LARGE
curl -s http://$IP:$P/../../etc/passwd --path-as-is
#   -> 404 NOT_FOUND               (no filesystem mapping)
for i in $(seq 1 10); do curl -s -o /dev/null -w '%{http_code} ' -X POST http://$IP:$P/api/pair -H 'Content-Type: application/json' -H "Origin: http://$IP:$P" -d '{"clientNonce":"00","proof":"00"}'; done
#   -> first 5 are 400, then 429  (pairing rate limit)
```
